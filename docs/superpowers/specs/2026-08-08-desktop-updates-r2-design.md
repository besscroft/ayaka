# R2 Desktop Update Service

## Goal

Serve the latest Windows x64 desktop release from the existing docs Cloudflare Worker while
keeping R2 access private to the Worker binding and exposing only public update metadata and
download URLs to clients.

## Release Layout

Each stable release is immutable and contains the files generated by electron-builder:

```text
releases/stable/v0.1.2/latest.yml
releases/stable/v0.1.2/paimon-0.1.2-setup.exe
releases/stable/v0.1.2/paimon-0.1.2-setup.exe.blockmap
```

The Worker scans `releases/stable/`, parses strict `major.minor.patch` versions, and selects the
highest directory containing a valid `latest.yml` and installer object. It validates the manifest
version, installer filename, checksum, and R2 object before returning a release.

## Worker API

- `GET /api/releases/latest?platform=win32&arch=x64` returns the stable release version,
  publication time, installer URL, manifest URL, size, and SHA-512 checksum.
- `GET /api/updates/win32/x64/latest.yml` returns the standard electron-updater manifest with
  installer paths rewritten to `https://ai-release.zzzvoid.com`.

Unsupported platform queries return `400`; an absent complete release returns `404`; malformed
manifests or invalid configuration return `502`. Responses use short CDN caching. The Worker only
accepts fixed release prefixes and safe installer basenames, so clients cannot select arbitrary R2
objects or external URLs.

Wrangler config uses the `RELEASES_BUCKET` R2 binding and these public variables:

- `UPDATE_R2_PREFIX=releases`
- `UPDATE_CHANNEL=stable`
- `UPDATE_DOWNLOAD_ORIGIN=https://ai-release.zzzvoid.com`

The `bucket_name` in `apps/docs/wrangler.jsonc` is a deploy-time value and must be replaced with
the actual R2 bucket name before deployment.

## Desktop Flow

The main process owns an `UpdateManager` backed by `electron-updater`. It is enabled only for
packaged Windows builds, disables automatic downloads, and schedules one silent check five seconds
after startup. The renderer reaches it only through typed preload IPC methods:

- `updates:getState`
- `updates:check`
- `updates:download`
- `updates:install`
- `updates:onStateChanged`

The About page presents check, download progress, and restart/install actions. Startup discoveries
produce one localized Sonner notification and open the About tab when selected. Update failures are
recoverable and never prevent the application from starting. The main process blocks restart while
an Agent session is active, preserving the downloaded update for a later retry. Code signing is
intentionally not configured in this phase.

## Website Flow

The docs homepage requests the latest JSON endpoint after hydration. Both primary download actions
use the returned R2 installer URL; until the request succeeds, they retain the repository Releases
URL as a fallback.

## Verification

Worker tests cover semantic version selection, manifest rewriting, unsupported platforms, and
missing artifacts. Desktop tests cover unsupported environments, update lifecycle events, download
progress, installation, and network errors. Final validation uses `vp check`, `vp test`, the full
desktop test/typecheck commands, and the docs build/typecheck commands.
